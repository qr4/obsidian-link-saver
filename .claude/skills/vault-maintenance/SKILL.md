# Vault maintenance

## How the vault works

The save service (`Tools/save-service`) turns a URL into one **entry**: a `- #tags` line, an
LLM summary, a `[[Dumps/…]]` attachment link, and the raw URL. Entries are
appended to a **leaf note** under `Areas/<area>/…`. A note whose name matches
its own folder (`hobbies/hobbies.md`) is a **folder note** — its Waypoint index
is generated by the service, never hand-edit it or file content there.

The **registry** maps each saved URL to `area_note` (path relative to
`Areas/`) and `area_entry` (the bullet's exact text). A forced re-save finds
the old bullet by searching that file for that text. The registry lives in
the service's SQLite database: set `SAVE_SERVICE_URL` (and
`SAVE_SERVICE_TOKEN` if it has one) in the environment or in
`Tools/save-service/client.env`, and `vault.py` reads and patches it over
the service's API. Unset, the registry scripts refuse to run.

## Non-negotiables

1. **Take the lock — around the read, not just the write.** The save service
   may be appending. Every write goes inside `vault.file_lock()`: an flock on
   `.vault-maintenance.lock`, plus a lease on the service's vault lock, which
   holds its Area writes until released (it keeps downloading meanwhile).
   Also check the service's queue in its web UI; entries it wrote moments ago
   may still be in flight through the sync. For migrations this is automatic: `Migration` is a
   context manager, so write plans as `with Migration() as m:` and it holds
   the lock from the read through the flush. Don't reach for `file_lock()`
   yourself there — a nested acquire blocks on itself.
2. **Back up first.** `cp -a Areas /tmp/…/backup-$(date +%s)` plus the
   registry (`curl $SAVE_SERVICE_URL/api/registry > registry-backup.json`).
   Restructures touch hundreds of files.
3. **Re-point the registry after every move.** Run `fix_registry.py --apply`.
   Skip it and the next `--force` re-save appends a duplicate next to the
   bullet it failed to find.
4. **Verify by URL accounting, not by eyeball.** Diff the sorted list of
   URLs in `Areas/` before and after; the only difference must be entries you
   deliberately dropped.
5. **Never re-point a record by substring.** URL prefixes collide
   (`hardbreak.wiki/introduction` is a prefix of a dozen others). Match whole
   lines.

## Workflow

```bash
cd .claude/skills/vault-maintenance/scripts
python3 test_vault.py      # parsing regression tests (fast, run after editing vault.py)
python3 diag.py            # audit: read this before changing anything
# write a plan.py using migrate.py's primitives, then:
python3 plan.py            # dry run - prints every op, writes nothing
python3 plan.py --apply    # Migration() holds the lock across read and write
python3 fix_registry.py --apply
python3 waypoints.py --apply   # asks the save service to regenerate indexes (or writes them if it doesn't manage them)
python3 diag.py            # confirm clean
```

`migrate.py` gives you `move`, `move_many`, `merge`, `delete`, `move_entry`,
`drop_entry`, `edit`, `retag`, `flush`. Operations address entries by a
substring of their text, never by line number, so a plan stays valid even if
the service appended while you were writing it. `find()` raises if the needle
doesn't match exactly one entry — a plan that references something ambiguous
fails loudly instead of editing the wrong bullet.

`waypoints.py` first creates a flag-only folder note for every directory
under `Areas/` that lacks one, then regenerates the indexes - through the
save service when it manages waypoints (`MANAGE_WAYPOINTS`), so only one
machine ever writes them. Two writers (the Obsidian Waypoint plugin on two
machines, or the plugin plus a script) produce sync conflicts on folder
notes; keep the plugin disabled in Obsidian.

## Traps that have actually bitten

- **`flush()` rewrites every note, so the lock has to cover the read.** It
  doesn't patch files — it writes each note back wholesale from the model
  built when `Migration` read the vault. Anything the service appended
  between that read and the flush gets reverted: no error, no conflict, just
  a lost entry. Locking only the write does *not* close the window, because
  the window opens at the read. `Migration` is a context manager that owns
  the whole span, and `flush()` refuses to run outside it; `test_vault.py`
  covers both. Note `file_lock()` flocks a
  fresh fd per call, so `flush()` verifies the lock rather than taking it —
  a nested acquire would deadlock against its own caller.

- **MOC notes have no `- ` bullets.** `flush()` deletes notes it considers
  empty; index notes built from headings and numbered lists look empty to it.
  It deleted all seven curriculum/series notes once. `has_prose()` now spares
  them — keep that guard if you touch the sweep.
- **A folder can't hold an order.** Waypoint sorts alphabetically, so a
  reading order or numbered series must be an index note with explicit
  numbering, not a folder. Index notes also link across areas, which folders
  can't — and course items legitimately land in several areas.
- **Slug regexes lie about series numbering.** Openers are often unnumbered
  ("Fear and loathing in the land of MCUs" *is* MCU land part 1) and later
  parts change prefix (`mcu-12-…` drops "land"). Three misses from one
  pattern. Use `chains.py <host>` to walk the archive's own back-links
  ("previous article"), then hard-code a verified number→slug table.
- **Substack injects a "you might enjoy" widget** whose links are
  indistinguishable from prose citations in the HTML. Always read the
  surrounding sentence before treating a back-link as continuity. A citation
  a year later is not an instalment.
- **`<a>` can wrap a heading rather than sit inside it.** Reaching for
  `find_next("a")` pairs each title with the *following* item's link — an
  off-by-one that yields a complete, plausible, entirely wrong ordering. Try
  `find_parent("a")` first, and cross-check the mapping a second way.
- **Two notes sharing a basename** make every short `[[wikilink]]` ambiguous.
  Check after adding subfolders — generic names like `editors/`, `databases/`,
  `hardware/`, `performance/` collide across areas. Prefix them
  (`clojure-editors/`). `diag.py` reports Areas-internal collisions only;
  Areas-vs-`Dumps/` ties are noise, Obsidian resolves those by proximity.
- **A note named after its own folder** collides with the Waypoint folder
  note and gets silently overwritten. The service guards against the model
  producing one; a migration can still create one by hand.
- **Parsing bugs here fail silently, not loudly.** Three shipped and each
  returned a confident, plausible, wrong answer: a `[^\]]+` wikilink body
  could never reach the closing `]]` past a bracket in an attachment name
  (`Asahi Linux [16292].mkv`), so 46 links matched *nothing* and were dropped
  from every check rather than reported broken — "0 stale links" was partly a
  false negative. `\S+` truncated URLs at their first space, so two unrelated
  comic scans both became `.../communism/Love` and were flagged as duplicates
  for weeks. And `is_content` keyed only on a URL, so MOC notes read as empty.
  All three are now covered by `test_vault.py` — run it after touching
  `vault.py`, and add a case for any new silent-wrong-answer bug.
- **Shell loops over `$(find …)` word-split** on the spaces this vault's
  filenames are full of. Iterate in Python, or use `-print0`/`-exec`.
- **Don't delete a page the summariser called empty.** It usually means text
  extraction failed, not that the page is worthless — one such stub was
  Lamport's *Time, Clocks, and the Ordering of Events*. Re-file it with a
  hand-written summary.

## Re-saving through the service

To re-file an existing entry, prefer a forced re-save over hand-editing:
`Tools/save-service/client/obsidian-save <url> --force --wait` (or
*Re-save* in the web UI). It goes through `replace_area_entry`, so the old
bullet is removed and the registry updated atomically.

It re-runs the summariser, which **re-resolves the topic area** — the entry
may move to a different (often better-named) note. Expect that, and check
afterwards that the vacated note wasn't emptied.

`--force` also drops the `filename` key when a save changes type (HTML capture
→ git clone), orphaning the old `Dumps/single_page/*.html`. Report those
rather than deleting: an HTML capture can hold things a clone doesn't, such as
a gist's comment thread.

## Source-type gotchas in the save pipeline

- **YouTube** URLs copied from a browser carry `&list=…&index=…`. Without
  `--no-playlist` (which `saver/media.py` passes), yt-dlp resolves the whole playlist (41s vs 4s, blowing the
  timeout) and `--dump-json` emits one JSON object per video, which
  `json.loads` can't read. The download path is worse: it fetches the entire
  playlist and files whichever video finished last.
- **Gists** are git repos and clone cleanly, but their paths aren't
  `/owner/repo`: `/<id>` is an anonymous gist and `/<user>` is an index page.
  Adding `gist.github.com` to `GIT_HOSTS` would read both as an author URL and
  kick off an org-wide repo scan. They get their own shape check keyed on gist
  ids being 20–32 hex chars. Gists rarely carry a README, so
  `find_gist_primary` falls back to the largest file — otherwise the clone
  lands in `Dumps/git` with nothing in `Areas` linking to it.

## Scripts

| script | purpose |
| --- | --- |
| `vault.py` | shared model: parse notes into entries, Obsidian link resolution, `file_lock()`, URL normalisation. Vault root derives from the script path; override with `OBSIDIAN_VAULT`. |
| `diag.py` | audit: stale/ambiguous links, name collisions, duplicate URLs and attachments, near-duplicate entries, untagged entries, oversized dirs |
| `migrate.py` | entry/note-level migration primitives + dry-run `flush()`. `Migration` is a context manager and holds the vault lock across the read-mutate-write cycle |
| `fix_registry.py` | re-point the save service's registry at post-migration paths |
| `waypoints.py` | create missing folder notes, regenerate Waypoint indexes (via the save service when configured) |
| `chains.py` | recover post series from a crawled site's back-link graph |
| `test_vault.py` | regression tests for the parsing primitives — run after editing `vault.py` |
